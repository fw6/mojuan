# ADR-0005: 书架追更以阅读进度为基线

- 状态：Accepted
- 日期：2026-10-13

## Context

书架追更要回答「这部收藏的作品有没有新话」。判据有两种取法：一是与读者的阅读进度比，
源上存在 chapterIndex 大于进度记录里 chapterIndex 的章节就算有新话；二是与上一次检查的
章节表快照比，差集即新话。

收藏记录里现成的可比字段只有 `lastChapter` 与 `updateTime` 两个字符串，各源的格式并不统一
（有的写「#123」，有的写话名，有的没有更新时间）；章节项的 `index` 是数值（MangaDex 之类
的源会出现 1.5 这样的小数）。章节表没有独立的取数接口，`detail` 一次返回 `{comic, chapters}`。

## Decision

追更基线取读者的阅读进度：进度记录里的 chapterIndex 即基线；收藏之后从未打开过的作品，
基线是收藏那一刻章节表里的最后一话 chapterIndex（收藏入口只有详情页一处，点收藏时章节表
已经在手上）。

未读数 = 源上 chapterIndex 大于基线的**非外链**章节数，书架角标显示的就是它。不保存
「上一次检查的章节表快照」。

## Rationale

- **数值可比**：chapterIndex 是数值，跨源可以直接比较；`lastChapter` / `updateTime` 是字符串，
  各源格式不一，做判据会误报。
- **不需要新增基线存储**：进度里已经有 chapterIndex，未读数只是把它与章节表比一次；快照
  方案要为每部收藏多存一份章节表，还要为从未打开过的作品单独定基线。
- **角标语义直白**：读者看到数字想的是「还有多少话要补」，而不是「上次看之后新增了几话」。

## Consequences

- 角标的语义是**未读**，不是「自上次检查以来新增」。跳读留下的空档不计入：读者从第 1 话
  直接跳到第 100 话，第 50 到 99 话不会被算进未读数。
- 追更状态（最近检查时间、基线之后的话序号、未读数）可以随时由收藏与进度重新算出，因此
  不进 WebDAV 备份，`BACKUP_VERSION` 保持 1，旧备份文件继续可用。
- 未读数要随阅读立刻变化，追更状态里存的是基线之后的**话序号列表**，而不是一个数字；
  数字每次进书架就地重算。
- 源改版或章节被删之后进度里的 chapterIndex 可能在新章节表里不存在。此时先用进度里同时
  记下的 chapterTitle 定位；两者都定位不到就不显示角标，把该作品标为「待重建」，读者打开
  详情页时以当前进度重建基线；进度在新表里也定位不到时，基线落到新表的最后一话非外链话上，
  读者视为已追平，不会误报积压。
